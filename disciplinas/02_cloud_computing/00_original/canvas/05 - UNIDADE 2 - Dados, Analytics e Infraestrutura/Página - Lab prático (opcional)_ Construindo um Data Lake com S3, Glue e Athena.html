Lab prático (opcional): Construindo um Data Lake com S3, Glue e Athena

Pessoal,

Durante a aula, construímos na prática um pequeno pipeline de Data Engineering utilizando serviços da AWS.

Neste laboratório, vocês poderão reproduzir a prática utilizando o ambiente AWS Academy Data Engineering Sandbox.

A ideia é trabalhar com um arquivo CSV, armazená-lo no Amazon S3, catalogar os dados utilizando o AWS Glue, realizar consultas com o Amazon Athena e, posteriormente, transformar os dados para o formato Parquet utilizando um Glue Job.

Fluxo da prática

CSV → S3 / RAW → Glue Crawler → Glue Data Catalog → Athena → Glue Job → S3 / TRUSTED (Parquet) → Glue Crawler → Glue Data Catalog → Athena

Ao final, teremos duas camadas principais de dados:

  • RAW: dados originais em CSV;

  • TRUSTED: dados transformados para Parquet e compactados com Snappy.

2. Criar o bucket no Amazon S3

Acesse o Amazon S3 e crie um único bucket para o laboratório.

Utilize um nome semelhante a:

lake-SEUNOME

O nome do bucket precisa ser globalmente único. Substitua SEUNOME por alguma identificação.

Dentro desse bucket, crie as seguintes pastas:

raw/
trusted/
athena-results/

A estrutura inicial deverá ficar:

lake-SEUNOME/
├── raw/
├── trusted/
└── athena-results/

Dentro da pasta raw/, crie:

raw/customers/

Faça o upload do arquivo customers.csv nessa pasta.

A estrutura deverá ficar:

lake-SEUNOME/
├── raw/
│   └── customers/
│       └── customers.csv
├── trusted/
└── athena-results/

3. Criar o banco no AWS Glue Data Catalog

Acesse:

AWS Glue → Data Catalog → Databases

Crie um banco chamado:

lab_lake

Esse banco será utilizado para armazenar os metadados das tabelas utilizadas durante o laboratório.

4. Criar o Crawler dos dados RAW

Agora vamos utilizar o AWS Glue Crawler para analisar o arquivo CSV e criar automaticamente uma tabela no Glue Data Catalog.

Acesse:

AWS Glue → Crawlers → Create crawler

Configure o Crawler:

Nome:

crawler_customers_raw

Fonte dos dados: Amazon S3

S3 path:

s3://lake-SEUNOME/raw/customers/

Selecione ou crie uma IAM Role com as permissões necessárias para que o Glue consiga acessar os dados no S3.

Configure como banco de destino:

lab_lake

Utilize o prefixo:

raw_

Finalize a criação e execute o Crawler.

Aguarde até que a execução seja concluída.

5. Verificar o Glue Data Catalog

Depois da execução do Crawler, acesse:

AWS Glue → Data Catalog → Tables

Deverá aparecer uma tabela semelhante a:

raw_customers

O Crawler deverá identificar automaticamente a estrutura do arquivo CSV.

O arquivo utilizado nesta prática possui as seguintes colunas:

  • customer_id

  • first_name

  • last_name

  • company

  • country

  • category

  • purchase_value

  • quantity

  • subscription_date

  • email

  • status

Verifique também se a localização da tabela aponta para:

s3://lake-SEUNOME/raw/customers/

6. Configurar o Amazon Athena

Agora vamos utilizar o Amazon Athena para consultar os dados diretamente no S3.

Acesse:

Amazon Athena

Na primeira utilização, será necessário configurar o local onde os resultados das consultas serão armazenados.

Utilize a pasta criada anteriormente:

s3://lake-SEUNOME/athena-results/

7. Consultar os dados RAW no Athena

Com a tabela raw_customers disponível no Glue Data Catalog, podemos realizar consultas utilizando o Athena.

Consulta 1 — Visualizar os primeiros registros

SELECT *
FROM raw_customers
LIMIT 10;

Observe os registros retornados pelo Athena.

Consulta 2 — Analisar vendas por país

SELECT country,
       COUNT(*) AS clientes,
       SUM(purchase_value) AS total_vendas,
       AVG(purchase_value) AS ticket_medio
FROM raw_customers
GROUP BY country
ORDER BY total_vendas DESC;

Essa consulta apresenta:

  • quantidade de clientes por país;

  • valor total das vendas;

  • ticket médio.

Consulta 3 — Analisar vendas por categoria e status

SELECT category,
       status,
       SUM(purchase_value) AS total
FROM raw_customers
GROUP BY category, status
ORDER BY total DESC;

Observe os resultados e também a quantidade de dados escaneados pelo Athena.

8. Criar o Glue Job para transformar os dados

Agora vamos transformar os dados da camada RAW para a camada TRUSTED.

Acesse:

AWS Glue → ETL jobs → Jobs → Create job

Escolha:

Visual with a source and target

Source

Configure a origem utilizando o Glue Data Catalog:

  • Database: lab_lake

  • Table: raw_customers

Transform

Adicione uma transformação:

Change Schema

Neste exercício, mantenha as colunas existentes.

Target

Configure o destino:

Format:

Parquet

Compression:

Snappy

S3 Path:

s3://lake-SEUNOME/trusted/customers/

Database:

lab_lake

Table name:

trusted_customers

Salve o Job e execute.

Aguarde até que o status seja:

Succeeded

Após a execução, os dados transformados deverão estar armazenados no mesmo bucket, agora na camada trusted/.

A estrutura deverá ficar semelhante a:

lake-SEUNOME/
├── raw/
│   └── customers/
│       └── customers.csv
├── trusted/
│   └── customers/
│       └── arquivos Parquet
└── athena-results/

9. Criar o Crawler da camada TRUSTED

Agora precisamos atualizar o Glue Data Catalog para reconhecer os dados transformados.

Crie um novo Crawler:

Nome:

crawler_customers_trusted

Data source: Amazon S3

S3 path:

s3://lake-SEUNOME/trusted/customers/

Database:

lab_lake

Table prefix:

trusted_

Execute o Crawler e aguarde a conclusão.

No Glue Data Catalog deverá aparecer:

trusted_customers

Abra a tabela e verifique que a classificação dos dados é:

Parquet

10. Consultar os dados TRUSTED no Athena

Agora vamos realizar novas consultas utilizando a tabela trusted_customers.

Consulta 1 — Visualizar os registros

SELECT *
FROM trusted_customers
LIMIT 10;

Consulta 2 — Clientes por país

SELECT country,
       COUNT(*) AS total_clientes
FROM trusted_customers
GROUP BY country
ORDER BY total_clientes DESC;

Consulta 3 — Clientes por ano de assinatura

SELECT SUBSTRING(subscription_date, 1, 4) AS ano,
       COUNT(*) AS total
FROM trusted_customers
GROUP BY SUBSTRING(subscription_date, 1, 4)
ORDER BY ano;

Consulta 4 — Clientes da China

SELECT first_name,
       last_name,
       company,
       email
FROM trusted_customers
WHERE country = 'China'
ORDER BY last_name;

11. Comparar RAW e TRUSTED

Agora compare as consultas realizadas sobre as duas camadas:

RAW

CSV

versus

TRUSTED

Parquet + Snappy

Observe principalmente a quantidade de dados escaneados pelo Athena.

Com apenas 1.000 registros, a diferença pode ser pequena. Porém, em ambientes reais, com milhões ou bilhões de registros, formatos colunares como o Parquet podem reduzir significativamente a quantidade de dados processados.

Esse é um dos motivos pelos quais formatos como Parquet são muito utilizados em arquiteturas de Data Lake e Data Engineering.

  • Qual é a função do AWS Glue Crawler;

  • O que é o Glue Data Catalog;

  • Como o Athena consulta dados armazenados no S3;

  • Qual é a função de um Glue Job;

  • Por que utilizar Parquet;

  • O que é a compressão Snappy;

  • Por que transformar os dados antes de realizar análises;

  • Como diferentes serviços AWS podem ser combinados para construir um pipeline de Data Engineering.
